# 个体户 L0→L3 Agent 协同设计

> 个体工商户 35 万户批量授信 · SDAFI v2.0 架构落地
> 配套文档:个体户 Agent 对应矩阵 · 玉林普惠金融信用评级与风控方案 · SDAFI 白皮书 v2.0
> 版本:2026-05

---

## 摘要

个体户与法人尽调虽共享 SDAFI 架构基础,但因业务场景差异巨大,L0→L3 协同结构需要**重新设计**。核心差异:

- **客群规模差异**:个体户 35 万户 vs 法人 10 万,关键路径必须从 105 秒压到 30-50 秒
- **风控范式差异**:个体户重反欺诈 + 失联,法人重交叉验证 + 经营恶化
- **主体结构差异**:个体户是"经营者本人 + 字号"双主体,法人是单主体
- **Agent 编排差异**:个体户多了一条**贷前快速否决通道**,以应对批量场景的成本压力

本文档完整描述个体户场景的 L0→L3 协同结构、关键路径、Critic 回路与工程纪律。

## 一、L0→L3 各层定义(个体户)

| 层 | 名称 | 包含 Agent | Agent 数 | SDAFI 阶段 | 关键纪律 |
|---|---|---|---|---|---|
| **L0** | 编排层 | SE-01 | 1 | Sense | 一票否决前置 + **五步反欺诈门控** + 双主体快照冻结 |
| **L1** | 原子工具层 | 4 个 MCP 工具组 | 0 | Sense 子组件 | 哑工具,只调 API 不判断 |
| **L2** | 章节分析层 | SP-A01 ~ SP-A05 | 5 | Decide | 5 个 Agent 并行(法人是 6 个,少了 LE-A04 财务) |
| **L2.5** | 横向分析层 | SP-A06 ~ SP-A07 | 2 | Decide | 等 L2 完成后并行启动 |
| **L3** | 决策与质检层 | SP-A08 / SP-A09 / SP-A10 | 3 | Decide | SP-A08 + SP-A09 并行 → SP-A10 Critic 串行核查 |
| **Act** | 执行层 | AC-01 | 1 | Act | 唯一写业务库 |
| **闭环** | 反馈与改进 | FB-01 / IM-01 | 2 | Feedback / Improve | **失联监控驱动改进** |

**总计 14 个 Agent**(法人 16 个),少了 LE-A04 财务诊断 + LE-A07 交叉验证(因个体户没有三表 + 无交叉验证维度对)。

但**新增了 2 个个体户特有的关键 Agent**:

- **SP-A04 反欺诈流水线 Agent**:对应第七章五步反欺诈,法人没有等价物
- **SP-A09 失联监控配置 Agent**:对应第九章贷后,失联是个体户最大贷后风险

## 三、与法人尽调的协同结构差异

### 差异 1 · L0 多了"五步反欺诈门控"环节

**法人 L0**:一票否决 → 授权门控 → 数据池抓取(3 步)
**个体户 L0**:一票否决 → 五步反欺诈 → 授权门控 → 双主体数据池抓取(4 步)

五步反欺诈门控是**实时同步执行**,任一步未通过直接拒绝,不进入 L2。这意味着 35 万户中**大量欺诈申请在 L0 就被拦截,不消耗 L2 的计算资源**。

预估命中分布(基于行业经验):
- 一票否决前置:命中率约 3-5%(失信/限高/空壳/黑名单等)
- 五步反欺诈:命中率约 8-12%(身份/手机/工商验真不通过)
- **L0 累计拦截率约 11-17%**——节省 35 万 × 15% × 后续接口费用

### 差异 2 · L2 少 1 个 Agent,但多了 SP-A04

**法人 L2**:6 个 Agent(LE-A01-A06)并行
**个体户 L2**:5 个 Agent(SP-A01/A02/A03/A05/A06)+ SP-A04 反欺诈流水线

SP-A04 是个特殊存在——**它是 D 阶段 Agent,但不调任何接口**,完全消费 SE-01 在 Sense 阶段已抓取的反欺诈数据,把五步流水线整理成第七章的可视化呈现(表 41-43)。

这是个体户场景对 SDAFI 纪律三"数据池为唯一介质"的极致体现:**反欺诈数据抓一次,呈现一次,不重复调用**。

### 差异 3 · L2.5 只有 2 个 Agent

**法人 L2.5**:LE-A07 交叉验证 + LE-A08 风险地图 + LE-A09 用途与还款(3 个)
**个体户 L2.5**:SP-A06 四维评分 + SP-A07 风险地图(2 个)

少的 LE-A07/A09 是因为:
- 个体户没有"五对交叉验证"(没有发票×营收、社保×年报这类规则)
- 个体户授信用途简单(进货/周转),不需要专门 Agent 分析

注意:**个体户的 SP-A06 四维评分被划到 L2.5**(法人是 L2)。原因是个体户场景下四维评分需要**综合 SP-A04 反欺诈结论**(若五步反欺诈某项弱通过,合规分要扣),所以必须等 SP-A04 完成后才能跑。

### 差异 4 · L3 多了 SP-A09 失联监控配置

**法人 L3**:LE-A10 授信结论 + LE-A11 贷后方案 + LE-A12 Critic
**个体户 L3**:SP-A08 授信结论 + SP-A09 失联监控配置 + SP-A10 Critic

SP-A09 是个体户特有 Agent。它和法人 LE-A11 的差异:
- LE-A11 配置贷后**经营恶化预警**(发票降幅 / 多头爆增 / 涉诉新增)
- SP-A09 配置**失联预警 + 多头爆增预警 + 经营异常预警**,失联是头号风险

具体配置规则差异:

| 监控项 | 法人 LE-A11 | 个体户 SP-A09 |
|---|---|---|
| 红灯触发 | 失信被执行 / 用电连续 3 月归零 / 破产 | **手机空号 / 停机 = 失联** / 字号注销吊销 / 新增失信 |
| 黄灯触发 | 多头月增>3家 / 财务异动 | 多头月增 1-2 家 / 逾期指数小幅恶化 |
| 监控频率 | 季频为主 | **月频为主**(失联检测必须高频) |

### 阶段耗时分解

| 阶段 | 个体户耗时 | 法人耗时 | 差异原因 |
|---|---|---|---|
| L0 一票否决前置 | 3-5 秒 | 5-8 秒 | 接口数少 1 个 |
| L0 五步反欺诈门控 | 8-12 秒 | — | 个体户特有 |
| L0 授权门控 | 0(已 H5) | 3-5 秒 | 个体户 H5 在前置阶段完成 |
| L0 数据池抓取 | 10-15 秒 | 15-20 秒 | 接口少(60 vs 90),无 RAG |
| L2 并行(关键路径) | 8-12 秒 | 30-40 秒 | **无 RAG,无财务深度,显著快** |
| L2.5 并行 | 5-8 秒 | 12-15 秒 | 少 1 个 Agent |
| L3 串行 | 6-10 秒 | 8-12 秒 | 略快 |
| AC-01 渲染 | 5-8 秒 | 8-10 秒 | 表少(62 vs 93),快 |
| **合计(无 Critic 退回)** | **约 35-50 秒** | **90-110 秒** | **快 2-3 倍** |

### 工程结论

**1. 个体户没有 RAG 瓶颈**
法人的 LE-A03 行业 RAG 是关键路径瓶颈(25-35 秒)。个体户没有 RAG 检索需求,SP-A02 调用烟草/电商接口直接拿数据,关键路径整段消失。

**2. 五步反欺诈是 L0 新瓶颈**
8-12 秒的反欺诈门控替代了部分时间,但**它是必要成本**——35 万户场景下不做反欺诈门控,后端会被欺诈申请淹没。

**3. 双主体快照增加抓取复杂度**
经营者本人 + 字号两套快照,字段哈希计算量翻倍。建议数据池存储时**用经营者身份证+字号信用代码作为复合主键**,避免后续查询时混淆。

**4. 35 秒目标是可达的**
端到端 35-50 秒,符合"35 万户批量授信"的场景需求(每秒可处理 2-3 笔申请,峰值 8 万次/天可消化)。

## 五、Critic 回路规则(个体户特化)

SP-A10 Critic 的拦截规则,在法人三类基础上增加一条**反欺诈一致性核查**。

### 四类拦截规则

**1. 数据对账型不一致 → 退回对应 SP-A0x**

例:SP-A06 给的经济能力分是 80,但 SP-A03 显示"无个税记录 + 无银行卡数据 + 无不动产"——按评分规则应是 30 分,矛盾。退回 SP-A06 重算。

**2. 跨章节逻辑型不一致 → 退回写报告的 Agent**

例:SP-A01 经营者画像说"无负面",SP-A08 授信建议却写"加强经营者风险条款"——前后矛盾,退回 SP-A08。

**3. 一票否决项遗漏 → 紧急退回 SE-01,触发 IM-01 复盘**

例:Critic 发现数据池里有"风险手机号"标签,但 SE-01 的反欺诈门控没拦下。这是严重事故,**触发紧急 improve_log 流程**。

**4. ★ 反欺诈一致性核查(个体户特有)**

例:SP-A04 五步反欺诈说"全部通过",但 SP-A06 维度三经营存续给出 30 分(低分)——反欺诈通过应意味着身份+手机+工商都真实,经营存续不应过低。Critic 判断这是数据矛盾,退回 SP-A04 + SP-A06 重新核对。

判断逻辑:
```
if SP-A04.五步状态 == "ALL_PASS" and SP-A06.维度三得分 < 50:
    return REJECT(target=[SP-A04, SP-A06], reason="反欺诈结论与经营存续矛盾")
```

这条规则在 35 万户场景下尤其重要——**反欺诈和经营存续是同一组数据(手机/工商/地址)的两个视角**,结果必须一致。

### 重试预算(个体户更紧)

| 第 N 轮 | 动作 | 时间预算 |
|---|---|---|
| 第 1 轮 | 退回 + 重跑 + 再 Critic | +20-30 秒 |
| 第 2 轮 | 再退回一次 | +20-30 秒 |
| **第 3 轮** | **不再重试,转人工**(法人允许 2 轮) | 切换到客户经理 |

注:个体户场景下 Critic 退回比法人更敏感——批量授信场景每多 30 秒成本可观,**所以个体户的 Critic 通过率必须更高**。如果 Critic 通过率长期低于 95%,IM-01 必须优先优化 Prompt。

## 六、L0→L3 协同的五条工程纪律(个体户特化)

在法人四条纪律基础上,个体户场景增加一条。

### 纪律一 · L0 不做业务判断,只做调度(共享)

SE-01 只判断硬性否决项 + 五步反欺诈门控,不做评分类判断。

### 纪律二 · L1 不做缓存判断(共享)

L1 拿到 API 返回原样写数据池,不替下游做 NULL 判定。

### 纪律三 · L2 内部禁止互相调用(共享)

SP-A04 反欺诈流水线**只能从数据池读 SE-01 已抓取的反欺诈接口结果**,不能直接 RPC 调 SE-01。

### 纪律四 · L3 Critic 不能被绕过(共享)

任何情况下 AC-01 都必须等 SP-A10 Critic 通过才能渲染,**没有"高分快速通道"**。

### 纪律五 · 双主体授权范围严格隔离 ★(个体户特有)

经营者本人的个人数据(银行卡/不动产/个税/婚姻/学历)和字号(店铺)的数据是**两个授权范围**,虽然附录 D.3 说明"经营者授权同时覆盖字号",但工程实现时**两个数据池必须分库存储**,授权撤回时支持分别撤回。

具体规则:
- 经营者撤回个人数据授权 → 个人数据池快照标记 expired,但字号数据可继续用于贷后监控
- 字号注销 → 字号数据池停止更新,但经营者个人数据若仍有效,贷后可继续监控经营者
- **不允许"打包授权打包撤回"**——这是《个保法》对个人信息精细化授权的要求

## 八、人在环 3 个节点(个体户)

| 节点 | 位置 | 人 | 职责 |
|---|---|---|---|
| **节点 1** | SE-01 启动前 | **经营者本人** | H5 实人核身 + 人脸识别 + 电签授权(覆盖经营者+字号双主体) |
| **节点 2** | AC-01 输出后 | 调查 / 复核 | 报告两方签字(模板表 53,比法人少了"部门负责人") |
| **节点 3** | IM-01 写 improve_log 前 | 风控负责人 | 审批所有模型 / 阈值 / Prompt 改动 |

**与法人的差异**:
- 节点 1:个体户**必须经营者本人在场**(H5 + 人脸识别),法人是企业代表签
- 节点 2:个体户**两方签字**(调查 + 复核),法人**三方签字**(多一个部门负责人)——金额小,流程简化

## 九、闭环驱动的特殊路径:失联反向驱动模型治理

个体户场景下,SDAFI 闭环最重要的输入是**失联事件**。

### 失联事件回写路径

```
贷后第 N 月
    │
    ▼ FB-01 月频调用『手机空号检测』
    │
    ▼ 发现空号 = 失联事件
    │
    ▼ FB-01 写 feedback_log:
       customer_id = X
       event_type = "失联"
       expected_score = 当时 SP-A06 的合规稳定分
       actual_outcome = "失联(空号)"
       deviation = 高分预测但失联,模型偏差
    │
    ▼ IM-01 季度复盘
    │
    ▼ 统计:近 3 月失联客户中,SP-A06 维度四(合规稳定)平均得分如何?
    │
    ▼ 如果失联客户的合规稳定分平均 70+,说明模型对失联预测能力不足
    │
    ▼ IM-01 提出改进建议:把"近6月欠费停机次数"权重从 15% 提到 25%
    │
    ▼ 风控负责人审批 → 写 improve_log
    │
    ▼ 下个版本 SE-01 + SP-A06 自动按新权重运行
```

这是 SDAFI 白皮书 §10.1 提到的"35 万户案例"的核心机制——**失联是个体户场景的独特反馈源,法人没有等价物**。

### 失联的早期预警信号

FB-01 不仅监控空号,还监控**失联前置信号**(白皮书 §10.2 提到的"领先指标"):

| 信号 | 阈值 | 时延(领先空号多久) |
|---|---|---|
| 月话费持续下降 | 连续 3 月环比降>30% | 提前 2-3 月 |
| 通话时长骤降 | 单月降>50% | 提前 1-2 月 |
| 欠费停机首次 | 第 1 次发生 | 提前 1 月 |
| 多头爆增 | 月增 ≥3 家 | 提前 1 月 |
| 字号经营异常 | 工商标记异常 | 提前 0.5-1 月 |

发现领先信号 → FB-01 触发**黄灯预警** → 客户经理人工介入(电话回访 / 上门),争取在真正失联前完成催收或重组。这是把"事后催收"变"事前干预"的关键。
